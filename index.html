How every number on this tab is counted
Internal reference. This sits inside the upload panel so the dashboard itself stays clean — the same notes are on the Summary & Method sheet of Export proof, which is the version to share.
Two questions per order, and only two
  1. Did it ship? Yes if it appears in the Avectous shipments file, or if NetSuite has a fulfillment. Either one counts.
  2. When was it created? The Date column. Everything about being behind is measured against this.
Why either system counts as shipped
Avectous is the source of truth for goods physically leaving. NetSuite's fulfillment is the accounting record and can lag by days. Counting only NetSuite understates what actually shipped.
Which ship date is used
Avectous RecordDate where available, otherwise NetSuite's Date Fulfilled. RecordDate is when the warehouse shipped; Date Fulfilled is when NetSuite found out.
How "days behind" is worked out
  1. Group orders by the day they were created.
  2. Walk back from today to the most recent day that is 90%+ shipped — that is the last day cleared.
  3. The gap from there to today is how far behind the warehouse is.
  4. Days with fewer than 50 orders are skipped, so a quiet day can't set the line.
Counting orders once
Orders are grouped by Internal ID, so an order with several rows counts once. Matching to Avectous uses PO/Check Number for sales orders and Document Number for transfer orders, because those are what Avectous stores.
What this tab does NOT do
It does not judge whether an order should have shipped. Holds, cancellations, backorder flags and payment blocks answer "why hasn't this shipped", which is a different question and lives on Integrations Status.
