How every number on this tab is counted
Internal reference. This sits inside the upload panel so the dashboard itself stays clean — the same notes are on the Summary & Method sheet of Export proof, which is the version to share.
Counting an order once
  1. Rows are grouped by Internal ID. An order with five rows still counts as one.
  2. Internal ID rather than PO/Check Number, because replacement orders reuse the original order's Shopify number — that column isn't unique.
  3. Transfer orders key on Internal ID too; Document Number gives the same answer.
Cancelled orders are excluded
  1. Any order whose WMS Status is Pending Cancellation, Cancellation Confirmed or Cancellation Failed.
  2. Any order whose NetSuite Status is Closed.
  3. CX is actively trying to stop these, so counting them as warehouse backlog blames the warehouse for orders nobody wants shipped.
  4. The excluded count is shown on each card and every one appears in the export ledger with state "cancelled".
Shipped vs not shipped
  1. Shipped — any line marked Fulfilled, including partially shipped orders.
  2. Not shipped — every line marked Unfulfilled.
  3. Partials count as shipped because something physically left the building; the remainder is a customer-service follow-up, not warehouse work in progress. The partial count is still shown separately.
  4. The two states always sum to the order count. A red warning appears on the tab if they ever don't.
How long shipping takes
  1. Date Fulfilled minus Date, in whole days, for orders that shipped.
  2. Where an order shipped across several days, the last day counts.
  3. Same day reads as zero.
How long the queue has been waiting
  1. Today minus Date, for orders with nothing shipped at all.
  2. Orders dated in the future are excluded — they can't be late yet.
  3. The "waiting longer than N days" figure uses the 90th percentile of actual ship time, so the line moves with the warehouse's own pace rather than being an invented target.
How far back the warehouse is caught up
  1. Orders grouped by Ship Date, never earlier than the order date.
  2. Ship Date rather than order date because a prebook placed in March with an August ship date is due in August, not five months overdue.
  3. Floored at the order date because a replacement order inherits the original's ship date — left alone, an order created on the 21st carrying a ship date of the 8th would look two weeks late the moment CX raised it.
  4. "Caught up through" is the most recent day at 95%+ shipped. "Where it falls off" is the sharpest single-day drop. Days with fewer than 50 orders are ignored for both, since small days swing wildly on percentage.
  5. Last 18 days shown; anything older is summarised underneath.
By channel
  1. Sales orders read channel from Order Type; transfer orders from Channel.
  2. Blank channels show as "Not set" rather than being dropped.
  3. The All channels row must equal the card above it.
Shipped per day
  1. Each order counted once, on the day it finished shipping, from Date Fulfilled.
  2. Last 21 days with activity.
Why there's no on-time percentage
Neither saved search carries a promised ship date. Ship by Date is blank on every transfer order, and where it exists it matches Ship Date exactly — which is itself the order date on 99.5% of rows. So the tab reports elapsed time rather than late vs on-time. If a real promise date gets added to 4866 or 4867, that changes.
